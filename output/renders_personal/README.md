# renders_personal — NOT DELIVERABLE

**Nothing in this folder may be used as evidence, cited in a report, or
presented as a measurement.** These images are made to look good, and
every choice that makes them look good disqualifies them:

| | |
|---|---|
| vertical exaggeration | heavy (up to 60x) and **not disclosed on the image** |
| colormaps | chosen for drama; not perceptually uniform |
| colour scales | per-render, so no two images are comparable |
| lighting | fabricated — multiple coloured key/fill/rim lights at angles no sun occupies |
| ambient occlusion | darkens creases well beyond anything physical |
| camera | picked for composition, not for showing the terrain honestly |

A viewer cannot tell real relief from stretched Z here, and is not meant
to. That is the whole difference between this folder and `output/figures/`.

## If one of these is ever wanted in a report

**Re-render it with `scripts/render_3d.py`**, which enforces the real
rules — exaggeration in the filename and burned into an on-image caption,
true-vs-apparent slope stated, defensible colormap, fixed scale where a
comparison is involved. Do not relabel an image from this folder. The
pixels are not the problem; the missing disclosure is, and a caption
pasted on afterwards does not make a fabricated light rig honest.

## Why the separation is a folder and not a filename convention

The predecessor project kept one high-exaggeration render whose reading
turned out to be an artifact, and marked it `ARTIFACT_EXAMPLE` in the
filename. That worked because it was one file. A whole set needs a
boundary that survives files being moved, renamed, or pasted into a deck —
hence a directory with this note in it.
